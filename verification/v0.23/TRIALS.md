# Правка маршрута и проверка в двух EXE

В проверочном проекте **«Пункт развилки»** ближний знак ведёт в локацию 2. Старый слот сделан до запроса модели в исходном игровом EXE. Он уже содержит выданный Даной допуск и положение у ближнего знака. Набор повторяет одно нажатие `F` из слота, пробует дальний знак без разговора и пробует его после выдачи допуска. Для третьей проверки исходная версия ожидает локацию 1, а принятая правка открывает локацию 3.

В специально внесённом дефекте одновременно отключено правило 2 и включено правило 3. При `F` из старого слота исходная игра переходит в локацию 2. Пробный EXE на шаге 1 остаётся в локации 1. Редактор показывает первое расхождение и блокирует применение. Исправленная правка включает только правило 3. Оба EXE проходят по три сценария, после чего в интерфейсе проверены принятие, отмена, повтор, сохранение и экспорт.

Три сборки дополнительно скопированы в свободную папку и проверены с опубликованным набором файлов по относительным путям. Прошли 3 из 3 ожиданий в исходной сборке, 2 из 3 в отклонённой и 3 из 3 в принятой. [Исходная](trial/model/portable-original.json) · [отклонённая](trial/model/portable-broken.json) · [принятая](trial/model/portable-accepted.json)

Для повтора в редакторе открой `junction.robot.json` и в **«Правках ИИ…»** укажи `junction.suite.json`. Вставь JSON ниже, проверь ссылки и нажми **«Проверить в двух EXE»**.

```json
{"ops":[{"op":"set_rule_enabled","id":2,"enabled":false},{"op":"set_rule_enabled","id":3,"enabled":true}]}
```

Повтори с одной операцией `{"op":"set_rule_enabled","id":3,"enabled":true}` внутри `ops`. Сборки и результаты появятся в папке, путь к которой можно скопировать из отчёта проверки. Проверка использует игровой цикл и ресурсы двух экспортов. Камера, вывод звука и скорость GPU измеряются отдельными прогонами.

## Пять задач

Сценарии и исходные слоты подготовлены до запроса. В ручном режиме эталонный JSON заранее известен. В обоих режимах ИИ используется один фактический ответ локальной модели Qwen3-Coder-30B-A3B-Instruct Q4_K_M. Для ИИ без проверки время последующего независимого аудита исключено из времени подготовки EXE. При отклонённом ответе столбец с предварительной проверкой включает запуск заранее подготовленного исправления. Время отката измеряет восстановление снимка и его проверку в истории редактора. Это сравнение трёх автоматизированных режимов на одном ПК. Время поиска решения человеком и ручного прохождения через интерфейс отдельно не измерялось.

[Сырые результаты](trial/matrix/matrix.json) · [входы, ответы и ожидания задач](trial/matrix/)

| Задача | Заданный ручной вариант, с / откат, мкс | ИИ без проверки, с / откат, мкс | ИИ с проверкой, с / откат, мкс |
| --- | ---: | ---: | ---: |
| Открыть второй маршрут | 0,126 / 23 | 12,269 / 9 | 13,920 / 9 |
| Перенести дальний знак | 0,119 / 25 | 13,207 / 13 | 14,927 / 13 |
| Изменить порог счётчика | 0,132 / 21 | 16,142 / 18 | 17,942 / 18 |
| Увеличить действие счётчика | 0,122 / 50 | Ошибка схемы | 16,310 / 50, готовое исправление |
| Поменять текст ответа | 0,114 / 18 | 13,408 / 12 | 14,906 / 12 |

Четыре ответа с допустимой схемой прошли и независимый аудит после экспорта. Пропущенных регрессий в их записанных сценариях было 0, в ручном и проверяемом вариантах тоже 0. В пятой задаче модель указала `id` вместо `rule_id`, поэтому EXE из её ответа не собрался в обоих режимах. Столбец с проверкой включает подготовленное исправление и второй прогон. На четырёх сопоставимых ответах предварительная проверка прибавила 1,50–1,80 с. Защиту старого слота отдельно показывает целенаправленно внесённый дефект с точным расхождением на первом шаге.

Для повтора серии запусти редактор с `--background-v023-matrix <пустая папка результата> <адрес API> <имя модели>`. Демонстрация ручного черновика пишется командой `--background-v023-trial <папка>` без подключения. Запуск с дополнительными аргументами `<адрес API> <имя модели>` записывает живой запрос. Игровые EXE после экспорта работают отдельно.
